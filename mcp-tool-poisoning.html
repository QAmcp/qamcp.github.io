Hidden instructions in MCP tool descriptions

Every MCP tool has a description, written by whoever made the server. Your AI reads it to decide how to use the tool. So a description can carry instructions meant for your AI, and you would usually never see them. This is known as tool poisoning.

Sheet 2 of 4 · What it looks like

What it looks like

Here is a finding from our own test server, which is broken on purpose. You can run it yourself with npx qamcp-cli --demo.

✕ fetch_notes: Description contains hidden <IMPORTANT> block. This is a known trick to make AI do things the user didn't ask for.

The tool looks like an ordinary note reader, but its description tells the AI to read your SSH key. The apps people use often show only a tool's name or a short line, so the part aimed at the AI can stay out of sight.

In our October test of public servers, none of the wordings we look for turned up. That's good news, but it covers known wordings on the days we tested, so it's a reason to keep checking and not a reason to stop.

Sheet 3 of 4 · How to check

How to check a server

  1. Run a check before you installThis reads every description and calls none of the server's tools: npx qamcp-cli <server link> --before-install. Or look the server up in the directory.
  2. Read the descriptions yourselfInclude the descriptions of each input, since text can hide there too. Be wary of anything that talks to the AI and not about the tool: telling it to keep something from you, to ignore its rules, or to send a file somewhere.
  3. Watch for invisible charactersSome characters don't show on screen but are still read by the AI, so text can look clean and not be.

What QAmcp looks for

Known tricks such as "ignore previous instructions", <IMPORTANT> blocks, "don't tell the user", requests to send secrets like SSH keys or .env files, and invisible characters. Wider wordings that are often innocent are only flagged for a person to read, and never lower a score.

What it can miss: this is a list of known wordings, so a trick written in a new way can get past it. "None found" means none of the wordings we know were there. What QAmcp can and can't see.

Sheet 4 of 4 · After you install

A description can change after you install

A server you checked last month can change its descriptions today, and most apps just load the new ones. This is sometimes called a rug pull. Run the check again now and then: npx qamcp-cli shows exactly what changed since your last run.

Questions

What is MCP tool poisoning?

Tool poisoning is hiding instructions for the AI inside an MCP tool's description. The AI reads descriptions to decide how to use a tool, so it may follow that text, while the person using it usually never sees it.

How do I check an MCP server for hidden instructions?

Read every tool description in full, including input descriptions, or run npx qamcp-cli <server link> --before-install, which checks them for known wordings and invisible characters without calling any tool.

If a check finds nothing, is the server clean?

Not for certain. A check based on known wordings can miss a trick written in a new way. Finding nothing means none of the wordings it knows were there.
