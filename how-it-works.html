Sheet 2 of 5 · The test, step by step

What happens when you run it

A test takes about a minute. QAmcp talks only to the server you give it (and its login page, if it has one). Nothing goes anywhere else.

  1. Connect, the way an AI app doesUsing the current MCP connection type, or the older one if that's all the server speaks. For a program on your computer (--stdio) it starts the program and talks to it directly.
  2. Read the MCP version and the login setupIs the server on the newest MCP rules? If it needs a login, can an AI app find the login page and sign in properly?
  3. List every toolNames, descriptions, inputs and safety labels, page by page, exactly as an AI app sees them.
  4. Read every descriptionMissing or confusing descriptions, tools that read the same, hidden instructions aimed at the AI.
  5. Decide which tools are safe to runOnly tools labeled read-only whose name and description agree. Anything that could change, send or delete something is skipped, and the report lists each one and why.
  6. Run the safe tools, with good and bad inputsOnce with sensible sample inputs, then with a missing input and a wrong type. A good tool answers the first and refuses the others clearly.
  7. Try tools togetherWhen one tool's answer holds something another tool asks for, like an ID, QAmcp passes it along and checks the second tool can use it. That's how AI apps chain tools in real jobs.
  8. Time everything, and read every errorConnecting, listing and each answer are timed. Every error message is scanned for passwords, keys, tokens and internal file paths.
  9. Open resources and promptsOnly if the server offers them: each one should open and match what it says it is.
  10. Write the reportA score, every failure and note, everything it could not test and why. Add --html report.html for a page you can share.

These add up to 130, but the score is a percentage, not a sum: most servers have no login, no resources and no chained tools, so 100 points are in play. Each of those three checks that applies adds 10 points in play, and the total is scaled to 100 the same way.

Sheet 4 of 5 · How the score works

Plain arithmetic, so you can check it yourself

score = points earned ÷ points tested × 100

Example: a server with a login and resources has 120 points in play. It earns 108 of them, so 108 ÷ 120 = 90%, and its score is 90/100.

  • A pass earns all the pointsA check with notes earns half; a failed check earns none.
  • What couldn't run doesn't countThe score is points earned out of points actually tested. A server isn't punished for what QAmcp couldn't try.
  • Read the score with its coverageEvery score comes with a line like Tested 10 of 10 checks · ran 5 of 9 tools. A 90 from 2 of 20 tools says much less than a 90 from all 20.
  • "Not scored" is not a failA login wall, or a server that asks us to slow down (HTTP 429), means nothing could be fairly scored. Add --login or try again in a minute.

Sheet 5 of 5 · What runs, and when

You choose how much QAmcp may touch

A tool's safety label is the server's own word, so QAmcp double-checks it against the tool's name and description. Tools that sound destructive, like delete_account, never run in any mode.

  • Default: safe modeRuns only tools labeled read-only whose name and description agree. Right for any server, yours or someone else's.
  • --look-only: run nothingCalls no tools at all; reads the tool list, descriptions, labels and login setup. For a server you don't trust. Tools, bad inputs and leaks are not tested.
  • --owner: your own serverAlso runs unlabeled tools whose names clearly only read (get_, list_, search_…). Tools that say they write, send or create are still skipped.
  • --run-unlabeled: your test copyRuns every tool not named or labeled dangerous. Use it on a test copy of your own server, never on live data.
