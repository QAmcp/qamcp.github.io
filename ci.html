Test your MCP server on every change

Add one file to your GitHub repository. Every pull request gets a comment with the score, and the build fails if the server got worse, before your users' AI apps notice.

Sheet 2 of 6 · Set it up

One file, three steps

  1. Create the fileIn your repository, add .github/workflows/qamcp.yml with the contents below. Change the url to your server's link.
  2. Commit itThat's the whole setup. GitHub runs it for free on public repositories.
  3. Open a pull requestQAmcp tests the server and comments the score. If the score is under 80, the check turns red. Later runs update that same comment instead of adding new ones.
name: QAmcp
on: [pull_request]
permissions:
  contents: read
  pull-requests: write   # to comment the score
jobs:
  qamcp:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: QAmcp/qamcp-cli@v0
        with:
          url: https://your-server.com/mcp
          fail-under: 80
Sheet 3 of 6 · A server that needs a key

Keep the key in GitHub's secrets

  1. Make a test keyCreate a key for your server that can only read, just for testing.
  2. Add it as a secretRepository → Settings → Secrets and variables → Actions → New repository secret. Name it MCP_TEST_TOKEN.
  3. Send it as a headerAdd these lines under with:. The key goes only to your server, and GitHub hides it in the logs.
          headers: |
            Authorization: Bearer ${{ secrets.MCP_TEST_TOKEN }}

Is your server a program instead of a link? Use stdio: npx -y your-mcp-server in place of url.

Sheet 4 of 6 · Catch what changed

Compare every run with the last one

With a baseline, QAmcp remembers the last report and fails the build if the score dropped by more than 5 points, a check started failing, or a tool was removed. Tools that changed are listed in the report and the tools-changed output, so you can decide what to do. That's how you catch a broken release before your customers do.

      # keep the last report between runs
      - uses: actions/cache@v6
        with:
          path: qamcp-baseline.json
          key: qamcp-${{ github.ref_name }}-${{ github.sha }}
          restore-keys: |
            qamcp-${{ github.ref_name }}-
            qamcp-main-
      - uses: QAmcp/qamcp-cli@v0
        with:
          url: https://your-server.com/mcp
          fail-under: 80
          baseline: qamcp-baseline.json
          save-baseline: qamcp-baseline.json

The first run has no baseline yet, and that's fine: it just saves one. The full example, with uploading the reports as files, is in examples/qamcp-ci.yml.

Sheet 5 of 6 · Any other CI

GitLab, CircleCI, Jenkins or your own script

Run the same command anywhere Node.js 20 or newer is installed. The exit code tells your CI what happened.

npx qamcp-cli https://your-server.com/mcp --fail-under 80 --baseline base.json --save-baseline base.json --junit report.xml
Exit codeMeans
0Fine: every rule you set passed
1A rule you set failed: score too low, a check failed, or the server got worse than the baseline
2Wrong options in the command
3Could not test: the server is down, needs a login, or asked us to slow down
