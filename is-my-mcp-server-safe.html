How to tell if an MCP server is safe

No test can prove an MCP server is safe. What you can do is find out who made it, what it can touch, and whether anything looks wrong, before you connect it to your AI. These six checks take a few minutes, and most of them are free to automate.

Six things to check before you install one

An MCP server gives your AI new abilities, and its text goes straight into what your AI reads. So it deserves the same look you would give any app you let near your files or accounts.

  1. Who made it, and where does it run?A server from the company whose product it connects to is a different thing from a copy by a stranger with a similar name. Check the link and the code repository. Then check where it runs: a remote server sees what you send it, and a local one runs as a program on your computer with your permissions.
  2. What can it change?Count the tools that only read and the ones that can change, send or delete. Tools carry safety labels for this, such as readOnlyHint and destructiveHint. In our October test of 1,806 tools, 156 (9%) had no safety label at all. A label is the server's own word, so read the tool's name and description too.
  3. Are there hidden instructions in its descriptions?A tool description can carry text aimed at your AI and not at you. This is called tool poisoning. We explain it in hidden instructions in MCP tool descriptions.
  4. Are there published security advisories?Look up the server's code in GitHub Security Advisories and OSV.dev. An advisory isn't a reason to walk away on its own: a project that publishes and fixes problems is doing the right thing. Check whether your version is fixed.
  5. What does it ask you to sign in with?Prefer a login that lets you limit what it can reach. Be careful with a server that wants a broad, long-lived key to an important account. Give it the smallest access that does the job.
  6. Does it change after you install it?A server can change its tools later, and a clean check last month says nothing about today. Check again now and then, especially after an update. npx qamcp-cli shows what changed since your last run.

What no test can tell you

A test sees what a server says and answers from the outside, on the day it ran. It can't see what happens to your data behind the scenes, what a server does only for some people, or what it will do next month. So a good score means no problems were found, not that there are none. What QAmcp can and can't see.

Questions

Can a test prove an MCP server is safe?

No. A test only sees what a server says and answers from the outside, on the day it ran. It can find real problems, but a clean result means none were found, not that there are none.

How do I check an MCP server before installing it?

Run npx qamcp-cli <server link> --before-install. It reads what the server says about itself, calls none of its tools, and lists which tools can delete, change or send things, and any hidden instructions it knows about.

Are read-only labels trustworthy?

A label is the server's own word. Most are honest, but a server can label a tool read-only when it isn't. Treat labels as a useful hint and not as proof.
